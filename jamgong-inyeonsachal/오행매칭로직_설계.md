# 잼공인연사찰 — 오행 매칭 로직 설계 v1.0

## 1. 전체 흐름

```
입력(생년월일시, 성별, 기도목적, 현재위치)
   ↓
① 사주 오행 분포 산출 (년/월/일/시주 → 8글자 → 오행 카운트)
   ↓
② 용신(부족 오행) 도출
   ↓
③ 기도목적 → 보완 오행 매핑
   ↓
④ 사찰 DB 스코어링 (오행 적합도 + 거리/방위 + 목적 태그)
   ↓
⑤ 상위 3곳 추천 + 근거 설명 생성
```

핵심 원칙: **단정적 표현 금지.** "100% 맞다"가 아니라 "참고용 추정치"로 오라클과 동일 톤 유지.

---

## 2. ① 사주 오행 분포 산출

- 입력: 생년월일시(양력/음력 선택), 성별(男/女 — 일부 신살 계산용, 필수는 아님)
- 만세력 변환 → 년주/월주/일주/시주 4개 간지(干支) 도출 → 총 8글자(천간4+지지4)
- 각 글자를 오행(목화토금수)으로 환산, 지장간(地藏干)까지 반영해 가중치 부여
- 결과: `{목: n, 화: n, 토: n, 금: n, 수: n}` 형태의 오행 분포표

> **재사용 대상**: 잼공 오라클의 명리 엔진에 이미 이 계산 로직이 검증되어 있음. 인연사찰은 독립 서비스이므로 **코드를 복사해 경량 버전으로 분리**하고, 추후 정식 연동 시 오라클 엔진 API 호출로 교체 (인터페이스만 미리 맞춰둠 → `calculateOhaeng(bornDateTime): OhaengDistribution`)

## 3. ② 용신(부족 오행) 도출

- 오행 분포에서 **개수가 0이거나 가장 적은 오행**을 1차 후보로 산정
- 일간(日干, 태어난 날의 천간) 기준 신강/신약 판단 로직까지는 이번 MVP에서 제외 (정통 명리는 용신 판단이 훨씬 복잡 — 오버클레임 방지 차원에서 "부족 오행 보완"이라는 쉬운 언어로 단순화)
- 출력 예: `{ 부족오행: "화", 근거: "사주 8글자 중 화(火) 기운이 0개로 가장 약함" }`

**정직성 처리**: 화면에는 "정통 사주 용신법의 간략화 버전이며, 정밀 감정은 오라클 정식 사주 서비스를 이용해달라"는 안내 문구 고정 노출

## 4. ③ 기도목적 → 보완 오행 매핑

| 기도목적 | 관련 오행 | 비고 |
|---|---|---|
| 재물운 | 금(金) | 전통적으로 금=재물 상징 |
| 건강운 | 토(土) | 중앙/안정 상징 |
| 학업/시험운 | 수(水) | 지혜/총명 상징 |
| 인연운(연애·화합) | 화(火) | 정열/관계 상징 |
| 가정운/평안 | 목(木) | 성장/화합 상징 |

→ 사용자가 고른 기도목적과 ②에서 나온 "부족 오행"이 **일치하면 가중치↑**, 다르면 두 오행을 모두 고려해 절충 추천

## 5. ④ 사찰 DB 스코어링

사찰 1곳당 아래 점수를 합산해 최종 점수 산출 (100점 만점 설계):

| 항목 | 배점 | 계산 방식 |
|---|---|---|
| 오행 방위 적합도 | 40 | 사용자 현재 위치 기준 사찰 방위(동/서/남/북/중앙) 실시간 계산 → 오행-방위 대응표(목=동, 화=남, 토=중앙, 금=서, 수=북)와 매칭 |
| 목적 태그 일치도 | 30 | 사찰 상세DB의 태그(관음도량/기도영험/전통명찰 등)와 기도목적 일치 여부 |
| 접근성 | 20 | 사용자 위치와의 실거리(가까울수록 高) — 너무 멀면 실행 가능성 낮아 매칭 의미 감소 |
| 데이터 신뢰도 | 10 | 상세DB(검증완료) 소속이면 만점, 기본DB(1,906개 중 미검증)면 감점 → 상세DB 사찰이 자연히 우선 노출 |

```
최종점수 = (방위적합도×0.4) + (목적일치도×0.3) + (접근성×0.2) + (신뢰도×0.1)
```

**오행-방위 대응표** (동양 전통 오행방위론):
- 목(木) → 동쪽
- 화(火) → 남쪽
- 토(土) → 중앙(반경 이내 근거리 전체)
- 금(金) → 서쪽
- 수(水) → 북쪽

방위 계산: `bearing(사용자위경도, 사찰위경도)` → 8방위(동/서/남/북/동남/동북/서남/서북)로 환산 → 오행 매핑

## 6. ⑤ 결과 출력 로직

- 상위 3곳 추천 (동점 시 상세DB 우선)
- 각 사찰에 대해 **근거 설명 자동 생성** (템플릿 조합, AI 생성 아님 — 오라클 원칙과 동일하게 사실 기반 조합)

```
예시 출력:
"회장님은 사주에서 화(火) 기운이 부족하여, 남쪽 방향에 위치하고 
화의 기운을 상징하는 [사찰명]과 인연이 깊은 것으로 나옵니다.
(참고용 추정치이며, 정밀 감정은 잼공 오라클 정식 사주 서비스를 이용해 주세요.)"
```

## 7. 데이터 구조 (인터페이스 확정)

```ts
interface OhaengDistribution { 목: number; 화: number; 토: number; 금: number; 수: number; }

interface TempleBasic {
  id: string;
  name: string;
  address: string;
  lat: number;
  lng: number;
  sect: string;        // 조계종/태고종 등
  verified: boolean;   // 상세DB 편입 여부
}

interface TempleDetail extends TempleBasic {
  foundedYear?: string;
  history?: string;
  tags: string[];       // 관음도량, 기도영험, 전통명찰 등
  officialSource: string;
}

interface MatchRequest {
  birthDateTime: string;
  gender?: "M" | "F";
  purpose: "재물운" | "건강운" | "학업운" | "인연운" | "가정운";
  userLat: number;
  userLng: number;
}

interface MatchResult {
  temple: TempleBasic | TempleDetail;
  score: number;
  reason: string;
}
```
