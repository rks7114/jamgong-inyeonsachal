## 왜 이 날짜인가

### 8/8 (토) 데모 — 甲寅 · +25.7

8/3~8/10 사이에서 유일하게 점수가 높다. 木 76.9%로 희신이 가득하고,
그 木이 용신 火를 살린다. 그 주 다른 날은 전부 음수다.

토요일이 오히려 데모에 맞다. 트래픽이 적을 때 조용히 올려 이틀 동안
링크를 눌러 보고 고칠 수 있다. 실수해도 보는 사람이 적다.

### 8/11 (화) 발행 — 丁巳 · +21.7

**천간도 火, 지지도 火.** 火 76.9%로 그 구간에서 가장 순도 높은 날이다.
회장님 사주에 火가 2.9%밖에 없으니 가장 모자란 것을 채우는 날이다.

화요일이라 주말에 묻히지 않는다. 데모가 사흘 먼저 살아 있으므로
책 안의 `jamgong.kr` 링크 37곳이 죽지 않는다.

### 앞서 잡았던 8/7을 버린 이유

일진이 癸丑, **水 50%로 용신 火를 끄는 날**이다. 46일 중 뒤에서 두 번째(−52.7).
하필 가장 필요한 오행을 끄는 날에 책을 낼 뻔했다.

### 더 좋은 날은 없는가

180일을 돌려 보면 최고점은 **丁卯 42.3점**이고, 60갑자 주기라 60일마다
같은 값이 돌아온다 — 8/21, 10/20, 12/19. **기다린다고 더 나은 날은 나오지 않는다.**
8/20 丙寅(+37.1), 8/21 丁卯(+42.3)이 더 높지만 3주 뒤라 일정이 맞지 않는다.

## 회장님이 하실 일 — 넷

| | 언제 | 무엇 | 시간 |
|---|---|---|---|
| **1** | 지금 | **정가 한 줄** — 권고 19,900원 | 1분 |
| **2** | 8/6 | 부크크 가입 · EPUB 업로드 · 심사 신청 | 30분 |
| **3** | 8/8 | 데모 배포 | — |
| **4** | 심사 후 | ISBN 번호 전달 | 1분 |

나머지는 전부 자동이다.

### 1 · 정가

```
정가 19900
```

A5 369쪽, 112,746자. 이 두께의 종이책이 서점에서 18,000~20,000원이고
전자책은 그 60~70%가 관례인데, 분량이 커서 상단이 맞다.
크몽 PDF는 별도 29,000원 — 노하우 상품은 싸면 오히려 안 팔린다.

### 2 · 부크크 등록 (8/6)

ISBN을 무료로 대행하고, 등록하면 교보·알라딘·예스24로 자동 유통되며,
초기 비용이 0원이다.

```
① 가입              사업자 330-34-01680
② 전자책 만들기 → EPUB 업로드
③ 도서정보 입력      ← ebook/sales-page/판매패키지.md 3절을 그대로 복사
④ 표지 업로드
⑤ 가격 입력 → 심사 신청
```

| | 파일 |
|---|---|
| 본문 | `ebook/dist/소문을끄고데이터를켜다.epub` |
| 표지 | `ebook/dist/` 안의 표지 이미지 (1699×2560) |
| 미리보기 | `ebook/dist/소문을끄고데이터를켜다-미리보기.epub` |

### 3 · 데모 배포 (8/8)

배포 후 반드시 확인할 것 — **책 안의 `jamgong.kr` 링크 37곳.**
하나라도 404면 "근거를 대지 않는 것은 팔지 않는다"고 쓴 책이 첫 장부터 무너진다.

### 4 · ISBN

심사를 통과하면 번호가 나온다. 그 번호를 주시면 판권과 EPUB 식별자가
함께 바뀐다(`urn:uuid:…` → `urn:isbn:…`). 유통사는 ISBN을 식별자로
기대하므로 판권만 고치고 파일을 두면 어긋난다.

**이 시점에 검수가 35/35가 된다. 그것이 국내 완료 신호다.**

## 아직 막혀 있는 것

**홍보가 나가지 않습니다.** 글은 만들어지는데 발행이 안 됩니다.

```
automation/threads/queue.jsonl   35건 · 2026-08-08 ~ 2026-09-06  대기 중
automation/logs/threads_*.jsonl  status: dry_run  reason: no_credentials
```

필요한 것은 둘입니다.

1. **Threads 앱 검수** — 메타에서 `threads_content_publish` 권한
2. **`THREADS_USER_ID` · `THREADS_ACCESS_TOKEN`**

**토큰은 채팅에 붙여넣지 마십시오.** 대화 기록에 남습니다.
서버의 `automation/.env`에 직접 넣으시면 코드는 손댈 것 없이 실제 발행으로 넘어갑니다.
